# Mafia Telegram Bot

Бот для записи на игры по спортивной мафии ВМК. С версии v3 архитектуры бот
**не подключается к базе напрямую** — все данные идут через общий backend API
(тот же, что обслуживает сайт клуба). См. `../../ARCHITECTURE.md`, раздел про
модель доверия бот-API.

## Что реализовано

- Регистрация пользователя (контакт, ФИО, статус по пропуску, предпочтение ролей, никнейм).
- Пользовательское меню: запись на игры (с резервом и авто-промоушеном при отмене),
  просмотр своих регистраций, редактирование профиля.
- Админ-меню (права выдаются через backend по конфигу или вручную другим админом):
  добавление/удаление админов, создание игровых дней пачкой слотов, редактирование/удаление
  игрового дня, список игр с составом.
- Раздел «Статистика» — теперь ссылается на сайт клуба (`/mafia`), где ведётся полная
  статистика и рейтинг по сыгранным играм.

## Запуск

1. Python 3.11+.
2. `pip install -r requirements.txt`
3. Поднять backend API (см. `../../backend/README.md`) — бот работает только вместе с ним.
4. `cp .env.example .env` и заполнить:
   - `BOT_TOKEN` — токен от BotFather;
   - `API_BASE_URL` — адрес backend API (например `http://localhost:8000` при локальном запуске,
     `http://api:8000` внутри docker-compose);
   - `BOT_SERVICE_TOKEN` — тот же секрет, что задан в `BOT_SERVICE_TOKEN` бэкенда.
5. `python bot.py`

Права первого администратора (bootstrap) настраиваются **на бэкенде**
(`SUPERADMIN_TELEGRAM_IDS_RAW` / `BOOTSTRAP_ADMIN_PHONE_RAW` в `backend/.env`), не в боте —
так самопожалование прав не может произойти в обход авторизации API.

## Структура

- `app/api_client.py` — HTTP-клиент к backend API (замена прежнего `app/db/database.py`).
- `app/handlers/*` — сценарии диалогов (aiogram Router), теперь вызывают `api: ApiClient`
  вместо прямых SQL-запросов.
- `app/keyboards/*`, `app/states.py` — без изменений по сути.
